# 1.2 安装指南

## 官方渠道与系统要求

请只从 **[ccswitch.io](https://ccswitch.io)**、**[GitHub Releases](https://github.com/farion1231/cc-switch/releases)** 或项目源码仓库获取 CC Switch。任何要求付费、充值或索取登录凭据的“CC Switch”网站或客户端都不是官方渠道。

| 系统 | 最低版本 | 架构 |
|------|----------|------|
| Windows | Windows 10 及以上 | x64 |
| macOS | macOS 12 (Monterey) 及以上 | Intel (x64) / Apple Silicon (arm64) |
| Linux | 见下方发行版说明 | x64 / ARM64 |

## 前置要求

### 安装 Node.js

CC Switch 管理的 CLI 工具（Claude Code、Codex、Gemini CLI）需要 Node.js 环境。

**推荐版本**：Node.js 18 LTS 或更高版本

#### Windows

1. 访问 [Node.js 官网](https://nodejs.org/)

2. 下载 LTS 版本安装包

3. 运行安装程序，按提示完成安装

4. 验证安装：

 ```bash
 node --version
 npm --version
 ```

#### macOS

```bash
# 使用 Homebrew 安装
brew install node

# 或使用 nvm（推荐）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
nvm install --lts
```

#### Linux

```bash
# Ubuntu/Debian
curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt-get install -y nodejs

# 或使用 nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
nvm install --lts
```

### 国内网络回退策略

CC Switch 的自动安装不会修改用户的全局 npm 配置。安装 CLI Agent 时，程序按以下顺序逐个尝试，只有上一条命令失败才会进入下一条：

1. npm 官方源 `https://registry.npmjs.org/`
2. npmmirror `https://registry.npmmirror.com/`
3. 华为云软件仓库 `https://repo.huaweicloud.com/repository/npm/`

Node.js 缺失时，Windows 和 macOS 也会先使用系统包管理器；包管理器不可用或下载失败时，自动切换到华为云 Node.js LTS 便携包，并校验 `SHASUMS256.txt`。便携版安装到 CC Switch 自己的运行时目录，不会覆盖系统已有 Node.js。

WorkBuddy 使用两个腾讯官方更新接口重试。若 Windows 接口没有提供 SHA-256，程序会验证安装包的 Authenticode 签名，且签名主体必须包含 Tencent；无法完成校验时不会执行安装。程序不会使用来源不明的第三方安装包或下载中转站。

### 安装前环境预检

安装页会在执行前检查 Agent 的必要环境：

- Claude Code 在 Windows 需要 Git for Windows 的 Git Bash 或 WSL；缺失时会阻止该项安装，并提供官方说明入口。
- Codex CLI、Claude Code 和 OpenCode 的 Node.js/npm 缺失或版本不满足时，CC Launch 会先自动准备 Node.js；npm 全局目录不可写时会尝试使用用户目录，不执行 `sudo npm install -g`。
- OpenCode CLI 在 Windows 没有 WSL 时仍可继续 npm 安装，WSL 只作为推荐项。
- WorkBuddy 的 .NET Runtime 和未来桌面版 OpenCode 的 WebView2 属于启动建议，不会阻止安装包下载。

完成 Git、WSL、WebView2 或 .NET Runtime 的手动安装后，点击安装页的“刷新状态”即可重新检测，不需要重启 CC Launch。

Codex UI 和 WorkBuddy 的 macOS 安装会优先复制到系统应用目录 `/Applications`；如果当前用户没有写入权限，则自动回退到 `~/Applications`。安装页会显示实际安装路径，状态检测只有在应用包同时包含 `Contents/Info.plist` 和 `Contents/MacOS` 可执行文件时才会标记为已安装。

安装页的进度面板会把任务拆成六个阶段：环境准备、解析来源、下载文件、完整性校验、执行安装和完成检测。下载类任务会显示已下载字节数与总大小；npm 或包管理器没有百分比时，会显示当前解析阶段和已接收的输出行数，不会伪造精确百分比。

安装确认页提供“后台安装 / Install in background”。点击后会关闭确认页，安装继续在后台执行，主窗口右下角的悬浮条会显示当前阶段和进度，因此可以继续配置供应商、API Key 和其他设置。安装完成后，每个已安装 Agent 都会显示中英双语使用说明，并提供“打开 / Open”按钮：桌面 Agent 直接启动应用，CLI Agent 会打开首选终端并执行对应命令。

### 从旧 CC Switch 迁移

安装页的“CC Switch 迁移 / CC Switch migration”区域支持只读检测旧版数据、导入用户选择的 CC Switch SQL 导出文件，以及打开平台卸载入口。导入会先经过临时数据库校验并创建备份；旧 `~/.cc-switch` 数据默认保留，不会复制 OAuth 登录态，也不会静默删除旧程序。迁移前应退出旧 CC Switch，避免两个程序同时写入 Claude、Codex、Gemini 等 Agent 的 live 配置。

“打开卸载入口 / Uninstall settings”只打开 Windows 应用设置或 macOS 应用目录，用户需要在系统界面确认卸载。旧配置、API Key、MCP、Skills 和备份不会因为卸载程序自动删除。

### Windows “此应用无法运行”排查

当前 Windows Release 提供 x64 安装包。若系统弹出“此应用在你的电脑上无法运行”，但 CC Launch 随后可以正常使用，优先确认弹窗对应的文件路径：

1. 检查是否误点击旧 CC Switch 快捷方式、旧版本安装器，或安装期间的 WebView2 引导程序。
2. 确认主程序位于 `%LOCALAPPDATA%\\cc-launch\\cc-launch.exe`，快捷方式目标也指向该文件。
3. 在 PowerShell 执行 `Get-CimInstance Win32_OperatingSystem | Select-Object OSArchitecture`，确认系统不是 32 位 Windows。
4. 使用 Release 附带的 SHA-256 文件校验安装包；当前包未签名，SmartScreen 或安全软件可能产生额外提示。
5. 在“事件查看器 -> Windows 日志 -> 应用程序”查看 `Application Error`、`SideBySide`、`Windows Error Reporting` 事件。

该提示通常不是用户目录权限问题。权限问题一般表现为无法写入、拒绝访问或 WebView2 安装失败；若无法确定触发进程，请保留弹窗截图、文件完整路径和事件查看器记录。

### Codex 网络修复

如果 Codex 在发送消息后反复显示重连，可以在“设置 → 代理 → 全局代理”中配置实际可用的 HTTP 或 SOCKS5 代理，然后开启“将此代理同步到 Codex”。

该功能会先通过代理测试 ChatGPT/OpenAI HTTPS 端点，再安全更新当前 Codex 配置目录中的 `.env`：

- HTTP/HTTPS 代理写入 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`。
- SOCKS5 代理写入 `ALL_PROXY` 和 `NO_PROXY`。
- CC Launch 只维护带有 `CC2CX CODEX PROXY` 边界标记的内容，不覆盖用户其他环境变量。
- 修改前会生成 `.env.cc2cx.bak`，写入使用私密权限和原子替换。
- 关闭开关时只删除 CC Launch 管理的代理块。

修改后必须完全退出并重新启动 Codex。该方式优先修复 Codex CLI、app-server、HTTPS 和 WebSocket；Codex 桌面界面的 Chromium 网络是否生效取决于当前应用版本和平台。

## Windows

### 安装包方式

1. 访问 [Releases 页面](https://github.com/farion1231/cc-switch/releases)
2. 下载 `CC-Switch-v{版本号}-Windows.msi`
3. 双击运行安装程序
4. 按提示完成安装

注意：运行安装程序后如果没有任何反应，可以在文件上点击右键，在弹出的菜单中打开 `属性`，`常规`页中的 `安全` 勾选 `解除锁定`

### 绿色版（免安装）

1. 下载 `CC-Switch-v{版本号}-Windows-Portable.zip`
2. 解压到任意目录
3. 运行 `CC-Switch.exe`

## macOS

### 方式一：Homebrew（推荐）

```bash
# 安装
brew install --cask cc-switch
```

更新到最新版本：

```bash
brew upgrade --cask cc-switch
```

### 方式二：手动下载

1. 下载 `CC-Switch-v{版本号}-macOS.dmg`（推荐）或 `CC-Switch-v{版本号}-macOS.zip`
2. 打开 DMG，或解压 zip 得到 `CC Switch.app`
3. 拖动到「应用程序」文件夹

### 已签名并公证

CC Switch macOS 版本已通过 Apple 代码签名和公证，可直接安装打开，无需额外操作。

## Linux

### ArchLinux

使用 AUR 助手安装：

```bash
# 使用 paru
paru -S cc-switch-bin

# 或使用 yay
yay -S cc-switch-bin
```

### Debian / Ubuntu

1. 根据架构下载 `CC-Switch-v{版本号}-Linux-x86_64.deb` 或 `CC-Switch-v{版本号}-Linux-arm64.deb`
2. 安装：

```bash
sudo dpkg -i CC-Switch-v{版本号}-Linux-*.deb

# 如果有依赖问题
sudo apt-get install -f
```

### AppImage（通用）

1. 根据架构下载 `CC-Switch-v{版本号}-Linux-x86_64.AppImage` 或 `CC-Switch-v{版本号}-Linux-arm64.AppImage`
2. 添加执行权限：

```bash
chmod +x CC-Switch-v{版本号}-Linux-*.AppImage
```

3. 运行：

```bash
./CC-Switch-v{版本号}-Linux-*.AppImage
```

## 验证安装

安装完成后，启动 CC Switch：

1. 应用窗口正常显示
2. 系统托盘出现 CC Switch 图标
3. 应用切换器中能看到已启用的受管应用，并能切换到目标应用面板

## 自动更新

CC Switch 内置自动更新功能：

- 启动时自动检查更新
- 有新版本时在界面显示更新提示
- 点击即可下载并安装

也可以在「设置 → 关于」中手动检查更新。

## 卸载

### Windows

- 通过「设置 → 应用」卸载
- 或运行安装目录下的卸载程序

### macOS

- 将 `CC Switch.app` 移到废纸篓
- 可选：删除配置目录 `~/.cc-switch/`

### Linux

```bash
# Debian/Ubuntu
sudo apt remove cc-switch

# ArchLinux
paru -R cc-switch-bin
```
