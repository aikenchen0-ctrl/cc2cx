# Agent 安装面板设计

## 目标

在 CC Switch 主工具栏提供“安装Agent”入口，让用户可以查看全部受管 Agent 的安装和可用状态，并在审阅安装命令与依赖后执行安装。

## 范围

- 固定展示 `AppType::all()` 的 9 个 Agent：Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi。
- 未安装条目显示安装按钮；已安装条目显示“已安装”和“可用/不可用”状态图标。
- 点击安装打开确认面板，展示平台命令、依赖检查结果和实时控制台。
- 安装完成后重新探测该 Agent，只有真实可执行时才显示“可用”。

## 非目标

- 不迁入 cc-boot 已废弃的 Node 配置写入逻辑。
- 不改变现有 Provider、MCP、Prompt 或 Agent 配置。
- 不为没有可靠自动安装方式的 Agent 编造安装命令；明确返回不支持原因。

## 架构

Rust 后端为每个受管 Agent 提供安装计划与探测结果。安装计划包含命令、依赖前置条件和是否可执行；执行端通过 Tauri 事件流发送 stdout、stderr 与结束结果。前端将其作为独立安装面板使用，并在完成后刷新列表状态。

## 交互与错误处理

- 列表打开时加载状态，刷新操作可以重新探测全部 Agent。
- “安装”只打开确认面板，不执行命令。
- 确认面板仅在所有必需依赖通过且计划支持当前平台时启用“确定安装”。
- 控制台逐行显示命令、标准输出、标准错误与退出码。
- 任一失败保留输出、明确显示失败原因，并允许重新探测或重试；不使用 fallback 或假成功路径。

## 验收

1. 工具栏在 Provider 视图展示“安装Agent”按钮。
2. 面板含全部 9 个 Agent，状态与实际探测一致。
3. 未安装 Agent 必须先经过命令/依赖确认面板才能执行安装。
4. 安装结束后状态重新探测，无法运行时明确标识为不可用。
5. Rust 单元测试覆盖安装计划与状态映射；前端测试覆盖打开、状态与确认流程。
